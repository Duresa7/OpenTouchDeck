# Media page

From M1-11 on, the `Media` page of the deck sends media and volume keys. A tap on a tile sends one consumer-control usage through the key engine, previous, play or pause, next, mute, volume down, or volume up, and each tile shows an icon over its caption. A consumer report carries no modifiers, so a Ctrl that is locked on the `F-Keys` page never goes out with a media key. In milestone 1 the engine's only sink is the console key log, so nothing reaches the PC. A swipe that starts on a tile sends nothing and changes the page. A developer or the harness injects taps with `touch tap`, finds each tile with `ui tile <id>`, and reads the reports from the key record with `$TD serial keys`.

## Sub-features

- `media-tap` sends `keys_consumer` with the tile's usage when a tap lifts inside the pressed tile. `prev` sends 182 (`0xB6`), `playpause` 205 (`0xCD`), `next` 181 (`0xB5`), `mute` 226 (`0xE2`), `voldown` 234 (`0xEA`), and `volup` 233 (`0xE9`). The record shows `con <usage>` and then `con 0`, and `keys state` reads the same afterward.
- `media-release-once` sends on release, never on press, so a hold on a tile sends once, at the lift. A 1000 ms hold on `mute` leaves exactly `con 226`, `con 0`.
- `media-no-modifier` leaves every modifier as it is. A media tap carries no modifier, and a Ctrl that is `LOCKED` on `F-Keys` stays `LOCKED` and adds no `kbd` report to the record.
- `media-swipe-quiet` sends nothing for a press that starts on a tile and becomes a swipe or a bounce.
- `media-tile-box` answers `ui tile <id>` for the six tiles, each 312 by 224 px. `prev` is at x 28, y 76 (centre 184, 188), `playpause` at x 356 (centre 512, 188), `next` at x 684 (centre 840, 188), `mute` at x 28, y 316 (centre 184, 428), `voldown` at x 356 (centre 512, 428), and `volup` at x 684 (centre 840, 428). `ui state` reports `tile_count` 6 while the page shows.
- `media-icons` draws a built-in LVGL symbol in Montserrat 48 over the tile's label. The icon is `text` (61311) and the label is a Montserrat 28 caption in `caption` (42360). The pair is centred on the tile with a 14 px gap, so the centre of the icon's label sits 22 px above the centre of the tile and the centre of the caption's label 33 px below it. The caption's box is the tile's width minus 16 px on each side, and it clips instead of wrapping. The symbols are `prev` 0xF048, `playpause` 0xF04B then 0xF04C, `next` 0xF051, `mute` 0xF026, `voldown` 0xF027, and `volup` 0xF028. The icon follows the usage the tile sends, so a tile bound to 205 gets the play and pause symbols whatever its id.
- `media-look-pressed` keeps the pressed look of every tile. A pressed media tile has the `glow` border, the `tile_down` fill, and the same icon and caption colors.

Tokens, as RGB565 decimals with hex and the PNG color they screenshot as: `caption` 42360 (`A578`, 165,174,198), `text` 61311 (`EF7F`, 239,239,255), `glow` 19743 (`4D1F`, 74,162,255), `tile_down` 10765 (`2A0D`, 41,65,107), `tile` 6406 (`1906`, 24,32,49), `bg` 2114 (`0842`, 8,8,16). `r5=r8>>3`, `g6=g8>>2`, `b5=b8>>3` gives the RGB565 values back exactly.

## How to get to it (user POV)

- Swipe left from `F-Keys`, or run `$TD serial cmd "ui goto 1"`, and tap a tile.
- Run `$TD serial cmd "ui tile volup"` for a tile's box, then `$TD serial cmd "touch tap <cx> <cy>"` to tap its centre.
- Run `$TD serial keys --out <file>` to read the record, and `$TD serial capture --no-reset --send "keys log on" --send "touch tap <cx> <cy>"` when the `keys:` log lines are the evidence.

## Driving it with touchdeck.ps1

Preconditions:

- The build under test is M1-11 or later, and `$TD serial doctor` exits `0` with `build_matches` true.
- Evidence directory `E=<absolute path>/.verify/<YYYYMMDD-HHMMSS>-media-page` is new, and Doctor's JSON is saved there as `doctor.json`.
- Start each recipe on page 1 at rest with every modifier `OFF` and the record empty. Run `$TD serial cmd "keys clear all"` and `$TD serial cmd "ui goto 1"`, wait a second, then run `$TD serial cmd "ui state"` and require `page` 1, `tile_count` 6, `animating` false, and an empty `pressed_tile`.
- Nobody touches the panel during an injection recipe.
- A recipe that reads the record runs `$TD serial cmd "keys record start"` first, `$TD serial cmd "keys record stop"` after, and then `$TD serial keys --out $E/<name>.json`, whose `brief` list reads each report as `kbd <mods> [<keys>]` or `con <usage>`.
- Aim each tap at the tile's `cx` and `cy` from `ui tile <id>`, or at the box listed under `media-tile-box`.
- Pixel reader, once per PowerShell session: `function px($f, $w, $x, $y) { $b = [IO.File]::ReadAllBytes($f); $o = ($y * $w + $x) * 2; $b[$o] + 256 * $b[$o + 1] }`. It reads a `--raw` screenshot. The fill probe of a tile at (`x`, `cy`) is (`x`+12, `cy`), which no icon or caption covers, and it reads 6406 at rest and 10765 while pressed.
- `scripts/media_look.py` checks the whole look from a full-size `--raw` screenshot and the tiles' `ui tile` replies. Save each reply as a key of one JSON object, `{"prev": {...}, "playpause": {...}}`, and run `python -I <skill dir>/scripts/media_look.py $E/media.rgb565 $E/tiles.json $E/media-analysis.json`. Exit `0` means every tile has its icon above its caption, both inside the 16 px inset and within 12 px of the centre column, and the fill probe reads `tile`. Add `pressed playpause` after the output path for a screenshot taken during a hold on `playpause`, and it also requires the 3 px `glow` border and the `tile_down` fill.

- **The Media page at rest (lane 2).** Run `$TD serial cmd "ui goto 1"`, wait a second, run `$TD serial cmd "ui state" > $E/media-state.json`, and run `$TD serial screenshot --out $E/media.png --raw $E/media.rgb565 > $E/media.json`. `ui state` reads `page` 1, `title` `Media`, `tile_count` 6, and `animating` false. The screenshot has `crc_ok` true. Run `media_look.py` on it. View `$E/media.png`. It shows `Media` at the top left, two rows of three tiles, and in each tile an icon over a caption, `Prev`, `Play/Pause`, `Next`, `Mute`, `Vol -`, and `Vol +`, with the second page dot lit. In the owner's run the icons started 65 to 72 px below the tile's top edge and the captions ended 64 to 69 px above its bottom edge, and the widest caption, `Play/Pause`, was 152 px wide in its 280 px box.
- **The key log, the You-see item.** Run `$TD serial capture --out $E/log --seconds 8 --no-reset --send "keys log on" --send "touch tap 512 188" --send "keys log off" --expect 'keys: \{"seq":\d+,"t":\d+,"type":"con","usage":205\}' --expect 'keys: \{"seq":\d+,"t":\d+,"type":"con","usage":0\}'`. Exit `0`. The first line is play or pause and the second is the empty consumer report, and `ui: click taps=N tile=playpause` follows. The log lines go through stdio, so the record is the proof when a count matters.
- **Play or pause twice (lane 3).** Start the record. Run `$TD serial cmd "touch tap 512 188" --repeat 2 --interval 0.25`, stop the record, and run `$TD serial keys --out $E/play.json`. `brief` is `con 205`, `con 0`, `con 205`, `con 0`, with `count` 4 and `dropped` 0. The owner's run had the two taps 273 ms apart on the board's clock.
- **Next and then previous, mute twice, volume up and then down, written from the plan and not run by the owner (lanes 4 to 6).** Start the record, tap `next` (840, 188) and then `prev` (184, 188), and `brief` is `con 181`, `con 0`, `con 182`, `con 0`. - **A locked Ctrl does not leak into media keys (lane 7).** Run `$TD serial cmd "keys clear all"` and `$TD serial cmd "ui goto 0"`. - **The pressed look.** Run `$TD serial screenshot --out $E/pressed.png --raw $E/pressed.rgb565 --background "ui hold 512 188 2000" > $E/pressed.json`. `background` names `playpause` in `pressed_tile`. Run `media_look.py` with `pressed playpause` and the `playpause` reply alone in `tiles.json`. `px "$E/pressed.rgb565" 1024 356 188` through `358` read 19743 and `px "$E/pressed.rgb565" 1024 368 188` reads 10765. View `$E/pressed.png`. `Play/Pause` has a lighter fill and a blue rim, and its icon and caption are as bright as at rest. - **The media tap time (perf).** Start the record. Run `$TD serial cmd "touch tap 840 428" --repeat 100 --interval 0.25 --time > $E/taps100.jsonl 2> $E/rtt100.txt`. In PowerShell, `$d = Get-Content $E/taps100.jsonl | ForEach-Object { ($_ | ConvertFrom-Json).deliver_us } | Sort-Object; $d[[int][math]::Ceiling(0.95 * $d.Count) - 1]` prints the p95 of `deliver_us` in microseconds, and the plan's bound is 60000. Stop the record. `count` is 200 with `dropped` 0. The owner's 40 taps read a p50 of 6987, a p95 of 9184, and a maximum of 11039, and 40 taps on `f5` read a p95 of 10997 against 10980 at M1-10.
- **Frame rate and free RAM.** Run `$TD serial cmd "perf fps 5" --timeout 8` alone, on page 1 and then on page 0. The owner read 85 frames on `Media` in four runs out of four, 17 fps, and 76 frames on `F-Keys`, 15 fps. Run `$TD serial cmd "heap"`. The owner read `free_internal` 128231 at M1-11, which is 1540 bytes under M1-10's 129771. That fits the six new icon labels at about 256 bytes each, an inference that nobody profiled.

## Gotchas

- Nothing reaches the PC in milestone 1. A record entry proves that the engine emitted the report, and a watcher on the PC would see nothing.
- A tile's box from `ui tile` holds only while its page shows. A tap aimed at `volup` while `F-Keys` shows lands on an F-Keys tile or a gap and may send a key or arm a modifier.
- A hold on a media tile sends on release, and so does `ui hold`. A recipe that holds a tile inside a record window adds that tile's `con` pair to the record.
- Space taps 0.25 s apart when timing them. A tap that lands inside the previous tap's 120 ms release fade waits one frame, about 65 ms on the deck.
- The icon and caption probes use the exact `text` and `caption` tokens, which only full-coverage pixels of a glyph reach. Anti-aliased edge pixels blend with the fill, so never probe a single pixel of a glyph. Read `media_look.py`'s boxes instead.
- `mute` draws the speaker symbol without waves and `voldown` draws it with one small wave. The captions, not the glyphs alone, tell them apart.
- The deck's frame rate with the `Media` page showing is 17 fps and with `F-Keys` it is 15 fps. Both are full redraws, so read each from a `perf fps` run that shares its serial session with nothing else.
- A `Media` tap never clears or sets a modifier, so a lock from `F-Keys` survives it. Run `keys clear all` between recipes.
- `ui tile` replies with `name`, the label. `ui tile voldown` has `"name":"Vol -"`.
- `touch tap` replies after LVGL has taken the release and run one more read, and the report leaves inside that window, so the record already holds a tap's reports when its reply arrives.
